# Internationalisation

- Catalogs: `packages/i18n/locales/<code>.json`, nested keys, ICU subset: `{name}` and `{count, plural, one {…} other {…}}` with CLDR categories and `=N` exact matches.
- 18 locales: en, es, pt, fr, de, it, nl, tr, ar, hi, bn, ur, id, fil, vi, th, ja, ko. RTL: ar, ur.
- The web app negotiates locale as account preference → last choice on this device → browser languages, sets `<html lang dir>`, and loads one ~2 KB catalog chunk.
- Dates, times, numbers and relative times use `Intl` with the account's time zone.
- Layout uses CSS logical properties so RTL mirroring needs no per-component work. Usernames and time zones are forced `dir="ltr"`.

## Validation (`pnpm i18n:check`, runs in CI)

For every locale: catalog exists, identical key set to English, no empty strings, valid message syntax, identical placeholders, every CLDR plural category for that language present (e.g. Arabic needs zero/one/two/few/many/other), no string identical to English unless allow-listed in `src/manifest.ts`, and RTL catalogs actually contain RTL script. Tests break catalogs on purpose to prove each check fires.

## Translation quality status

English is the source. **All 17 other catalogs are drafts written without native-speaker review** and are labelled "draft" in the language picker. To promote a locale to `reviewed`, a fluent reviewer checks every string in context, then the manifest entry is changed and the reviewer and date are recorded here.

## Adding a language

1. Add the code to `SUPPORTED_LOCALES` (and `RTL_LOCALES` if needed) in `packages/contracts/src/constants.ts`.
2. Add `packages/i18n/locales/<code>.json` and a manifest entry.
3. Run `pnpm i18n:check`. No application code changes.
